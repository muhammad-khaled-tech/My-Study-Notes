## 1. The Core Problem (The "Why")

> *In 2–3 sentences, what specific real-world pain point are you solving? Who suffers from this most?*

Developers waste an estimated **35% of their working time** not writing new features, but deciphering *why* existing code was written the way it was. Every time a senior engineer leaves a team, the institutional knowledge behind critical decisions — the constraints, trade-offs, and emergency compromises — vanishes with them. This problem hits hardest on engineering teams maintaining complex legacy codebases, and on the **4.5 million Arabic-speaking MENA developers** who have zero localized tooling to help them navigate English-only developer ecosystems.

---

## 2. The Solution & Value Proposition (The "What")

> *Describe the app. How does it solve the problem above? What is the single most important benefit for the user?*

**DevArcheology AI** is a two-surface platform that serves two distinct users inside the same engineering organization: the **individual developer** who needs instant context while coding, and the **Tech Lead or Engineering Manager** who needs a bird's-eye view of their team's collective knowledge health.

---

### Surface 1 — VS Code Extension *(The Developer's Companion)*

Installed in seconds from the VS Code Marketplace, the extension attaches silently to any repository. When a developer hovers over any line of code, a tooltip surfaces the complete story of that line:

- **Who** wrote it and when
- **Which Pull Request** it came from, including the code-review debate
- **Which Jira ticket** justified the business decision behind it
- **Which Slack conversation** led to the final implementation choice
- **Technical debt warning** if the code carries known risks or unresolved trade-offs
- **Arabic explanation toggle** — the full story rendered in Arabic for MENA developers

The full story panel also provides an interactive **timeline view** of the code's entire evolutionary history, with clickable source citations the developer can verify directly. All of this is generated by a 5-agent AI pipeline in **under 5 seconds**, without the developer ever leaving their IDE.

---

### Surface 2 — Web Admin Portal *(The Tech Lead's Command Centre)*

The Web Admin Portal is where DevArcheology transforms from a developer convenience into a **strategic engineering intelligence tool**. A Tech Lead or Engineering Manager logs in and sees their entire organization's knowledge health at a glance — scoped to their company's projects, repositories, and the specific teams using the extension.

**Key views inside the Admin Portal:**

- **Tech Debt Heatmap**
  A file-level heatmap across every project the team is assigned to. Red zones flag modules where a high percentage of decisions have no surviving documentation — Jira tickets closed, Slack threads deleted, PR comments lost. The Tech Lead sees exactly where the codebase is most fragile *before* a bug report arrives.

- **Knowledge Concentration Risk**
  A per-developer breakdown showing what percentage of critical business logic is understood by only one person. If Ahmed owns 34% of the payment module's undocumented decisions, the Tech Lead is looking at a live single point of failure. This view makes bus-factor risk visible and actionable.

- **Team Activity & Story Usage**
  Shows which developers are actively using the extension on their assigned projects, how many stories were generated per project per day, and which files are queried most frequently — a direct signal of where the team is spending the most time on context-gathering rather than building.

- **Onboarding Time Tracker**
  When a new developer is assigned to a project, the portal tracks their story generation rate during the first weeks. Declining usage signals growing confidence. The Tech Lead gets an estimated **time-to-productivity metric** for every new hire without a single survey or check-in meeting.

- **Project-Level Summaries**
  Each assigned project has its own summary page: overall context coverage score, most-queried files, top contributors, and an exportable report the Tech Lead can bring directly to sprint planning or an engineering all-hands.

---

### Single Most Important Benefit

A developer gets the full story behind any line of code in **under 5 seconds** without leaving VS Code.
Simultaneously, their Tech Lead finally has a live map of where the team's institutional knowledge is strong, where it is dangerously concentrated, and where it is already gone — all tied directly to the real projects their teams are working on.

## 3. The AI Trinity Strategy (The "How")

> *Explain how the project utilizes LLM, RAG, and Agents to create a "moat" or a superior experience.*

### LLM (Intelligence)

**Models used:** GPT-4 · Claude 3.5 Sonnet · Gemini (fallback)

**Primary role:** GPT-4 powers the final Story Synthesizer (Agent 5), producing grounded narratives with inline source citations for every claim. Claude 3.5 Sonnet handles deep technical code analysis. Gemini serves as a quota-exceeded fallback. Tiered model routing reserves expensive models for complex, uncached queries — keeping the blended cost at or below **$0.017 per story**.

Critically, Agent 5 is prompted as a *historian, not a speculator*: if retrieved context is insufficient to answer confidently, it emits a **low-confidence flag** rather than hallucinating an answer.

---

### RAG (Knowledge)

**Data sources indexed:** Git commits · GitHub PR discussions · Jira tickets · Slack threads

**Strategy:** All sources are embedded using OpenAI `text-embedding-3-small` and stored in **Pinecone** with rich metadata tags: `file_path`, `author`, `commit_hash`, `date`, `source_type`. Queries use **Hybrid Retrieval** — simultaneous semantic vector search and metadata-filtered retrieval — fused via Reciprocal Rank Fusion before the context window is assembled.

GitHub, Jira, and Slack webhooks maintain real-time delta sync. Deleted messages are soft-deleted and surfaced as *"source no longer available"* rather than silently dropped, preserving the honesty of every generated story.

---

### Agents (Action)

**Orchestration:** LangGraph (5 specialized agents in a parallel-then-sequential pattern)

| Agent | Name | Task |
|---|---|---|
| 1 | Git Archaeologist | `git blame` / `log` / `diff` — who, when, what changed |
| 2 | PR Context Retriever | GitHub PR discussions, code-review debates, rejected alternatives |
| 3 | Issue Tracker Linker | Jira/Linear tickets — the business reason behind the code |
| 4 | Communication Archaeologist | Slack threads — the decision moment and trade-off conversation |
| 5 | Story Synthesizer | Combines all context → cited narrative + tech-debt flag + recommended actions |

**Agents 1–4 run concurrently** as async LangGraph nodes, reducing the critical-path latency to the slowest of the four rather than their sum. Agent 5 runs sequentially on their merged output. LangSmith logs the full trace of every agent decision, making every story fully auditable.

### Risk Factor

**Primary risk — Cold Start & Team Data Bootstrapping**

The most critical challenge is the cold-start experience on *both* surfaces.

For the **extension**: a new developer's repository has zero indexed data on day one. Mitigation: incremental indexing prioritizes the most recent 90 days first, surfacing real value within minutes, while a progress indicator in the VS Code sidebar sets honest expectations throughout.

For the **Admin Portal**: the Tech Lead dashboard is only meaningful once several developers on the team are actively using the extension. Mitigation: the onboarding flow prompts the Tech Lead to invite team members immediately after account creation, and the dashboard displays a clear **coverage meter** (e.g., *3 of 8 developers connected*) until the team is fully onboarded.

**Secondary risk — API Cost at Scale**

Mitigated via tiered model routing (cached stories cost $0, simple queries route to GPT-3.5-turbo/Haiku, complex queries escalate to GPT-4/Sonnet), targeting a blended cost of **≤ $0.017 per story**. Enterprise B2B pricing above **$40/developer/month** ensures positive unit economics at scale.
