يا هلا يا خالد، السكربت ده "أساسي" لأي حد عايز يبني Backend احترافي. جوناس هنا بيشرح الـ **Environment Variables** (متغيرات البيئة)، ودي باختصار هي "كتالوج التشغيل" بتاع البرنامج بتاعك حسب هو شغال فين.

بما إن الموضوع دسم، هقسمهولك لـ **3 أجزاء رئيسية** عشان نهضمه حتة حتة:

## الجزء الأول: يعني إيه Environment Variables وليه بنوجع دماغنا بيها؟

تخيل إنك بتبني عربية (الـ App بتاعك). وأنت في المصنع (Development)، بتحتاج أجهزة قياس وتجارب كتير. لكن لما تطلع العربية للزبون في الشارع (Production)، بتشيل كل أجهزة القياس دي وبتهتم بس إن العربية تمشي بأمان.

### ليه بنستخدمها؟

1. **اختلاف الإعدادات:** في الـ **Development** ممكن تستخدم قاعدة بيانات للتجارب (Local DB)، لكن في الـ **Production** لازم تستخدم قاعدة بيانات حقيقية (Cloud DB).
    
2. **الأمان (Security):** ما ينفعش تكتب الباسوردات أو الـ API Keys "جوه الكود" (Hardcoded)، لأن أي حد هيشوف الكود على GitHub هيعرف أسرارك. بنحطها في متغيرات بره الكود خالص.
    
3. **التحكم في الـ Logging:** وأنت بتطور، عايز الـ Terminal يطبع لك كل حركة بتحصل (`Morgan logger`)، لكن في الـ Production ده بيبطأ السيرفر وبيملى الـ Logs على الفاضي، فبنقفله.

## الجزء الثاني: الـ `process.env` والتعامل مع Node.js

Node.js عنده كائن عالمي (Global Object) اسمه `process`. وجواه حاجة اسمها `env` دي اللي بيتخزن فيها كل المتغيرات اللي الـ System عارفها.

### إزاي بنعرف متغير جديد؟

جوناس شرح طريقتين:

1. **عن طريق الـ Terminal (الطريقة اليدوية):**
    
    ممكن وأنت بتشغل السيرفر تكتب كده:
    
    `NODE_ENV=development X=23 nodemon server.js`
    
    هنا Node هيفهم إن فيه متغيرين اسمهم `NODE_ENV` و `X` قيمتهم كذا، وهيبقوا متاحين في الكود عن طريق `process.env.NODE_ENV`.
    
2. **عن طريق ملف `.env` (الطريقة البريمو):**
    
    مش منطقي كل مرة تكتب 20 متغير في التيرمينال. فبنعمل ملف اسمه `config.env`.
    
    - **ملاحظة:** العرف إن أسماء المتغيرات تكون **UPPERCASE** زي: `PORT=3000`.
        
    - **ملاحظة تانية:** جوناس نصح بـ extension في VS Code عشان تلون لك الملف ده.
        

### مكتبة `dotenv`:

Node.js لوحده ما بيعرفش يقرأ ملفات الـ `.env`. هنا بنستخدم مكتبة `dotenv`. وظيفتها إنها تروح للملف، تاخد اللي فيه، وتحطه جوه الـ `process.env` عشان الكود يشوفه.

JavaScript

```
const dotenv = require('dotenv');
// السطر ده هو اللي بيعمل السحر وبيقرأ الملف
dotenv.config({ path: './config.env' });
```

## الجزء الثالث: الـ Trap (الفخ) اللي وقع فيه جوناس والترتيب الصح

دي أهم حتة في الفيديو. جوناس واجه مشكلة إن الـ Logger ما اشتغلش، واكتشف إن السبب هو **"ترتيب الأكواد"**.

### المشكلة كانت فين؟

هو عمل `require('./app')` (اللي جواه الكود اللي بيستخدم المتغيرات) **قبل** ما يعمل `dotenv.config()`.

فالـ `app.js` اشتغل ودور على `process.env.NODE_ENV` لقاه لسه فاضي (Undefined)، فما شغلش الـ Logger.

### الحل:

لازم دايماً تحمل الإعدادات (Environment Variables) **أول حاجة خالص** في ملف الـ `server.js` قبل ما تنادي على أي ملف كود تاني بيعتمد عليها.

## ملخص سريع عشان "أوبسيديان":

- **NODE_ENV:** متغير "عرفي" بنحدد بيه إحنا في أنهي مرحلة (dev ولا prod).
    
- **process.env:** المخزن اللي Node بيشيل فيه المتغيرات دي.
    
- **dotenv:** الأداة اللي بتنقل المتغيرات من ملف الـ `.env` للمخزن.
    
- **Conditional Logic:** بنستخدم `if (process.env.NODE_ENV === 'development')` عشان نشغل أكواد معينة في التطوير بس.
    

**يا بطل، هل الحتة بتاعة الـ "Order of Code" (ترتيب الكود) واضحة بالنسبة لك؟ ولا تحب أشرحلك ليه الـ require بتفرق في اللحظة دي بالذات؟**
