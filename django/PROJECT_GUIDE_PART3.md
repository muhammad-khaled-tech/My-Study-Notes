## 9️⃣ `core/urls.py` — App URL Routing

```python
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from . import views
```
- `path` — function to define a URL pattern.
- `include` — function to include another set of URLs.
- `DefaultRouter` — **DRF's magic URL generator**. It auto-creates URLs for ViewSets.
- `from . import views` — import the views module from the current package (core).

### The Router (for API ViewSets)

```python
router = DefaultRouter()
router.register(r"students", views.StudentViewSet, basename="student")
router.register(r"grades", views.GradeViewSet, basename="grade")
```
- `DefaultRouter()` — creates a router instance.
- `router.register(prefix, viewset, basename)`:
  - `r"students"` — the URL prefix. The `r` means "raw string" (no special character processing).
  - `views.StudentViewSet` — which ViewSet to use.
  - `basename="student"` — used to generate URL names (`student-list`, `student-detail`).

> [!IMPORTANT]
> **What does `router.register` actually create?**
> Just these 2 lines auto-generate ALL these URLs:
> | URL | Name | View Action |
> |-----|------|------------|
> | `api/students/` | `student-list` | List all / Create new |
> | `api/students/{pk}/` | `student-detail` | Retrieve / Update / Delete |
> | `api/grades/` | `grade-list` | List all / Create new |
> | `api/grades/{pk}/` | `grade-detail` | Retrieve / Update / Delete |

### URL Patterns

```python
urlpatterns = [
    # ── Template views ──
    path("", views.home_view, name="home"),
```
- `""` — empty string = the root URL (`http://localhost:8000/`).
- `views.home_view` — when someone visits `/`, call the `home_view` function.
- `name="home"` — a name for this URL. In templates, you can do `{% url 'home' %}` to generate the URL string.

```python
    path("login/", views.login_view, name="login"),
    path("logout/", views.logout_view, name="logout"),
```
- `/login/` → login page. `/logout/` → logs out and redirects.

```python
    path("students/", views.student_list, name="student_list"),
    path("students/add/", views.student_add, name="student_add"),
    path("students/edit/<int:pk>/", views.student_edit, name="student_edit"),
    path("students/delete/<int:pk>/", views.student_delete, name="student_delete"),
    path("grades/add/", views.add_grade, name="add_grade"),
```
- `<int:pk>` — a **URL parameter**. `<int:pk>` means "capture an integer from the URL and pass it to the view as `pk`".
- Example: URL `/students/edit/5/` → calls `student_edit(request, pk=5)`.

```python
    # ── REST API — Auth ──
    path("api/register/", views.RegisterAPIView.as_view(), name="api_register"),
    path("api/login/", views.LoginAPIView.as_view(), name="api_login"),
    path("api/logout/", views.LogoutAPIView.as_view(), name="api_logout"),
```
- `.as_view()` — **converts a class-based view into a function** that Django can use.
  - Django's URL system expects functions: `path("url/", some_function)`.
  - Class-based views aren't functions, so `.as_view()` creates a wrapper function.

```python
    # ── REST API — Data (auto-generated by router) ──
    path("api/", include(router.urls)),
]
```
- `include(router.urls)` — inserts ALL the auto-generated router URLs under `api/`.
- So `router.register("students", ...)` creates `api/students/` and `api/students/{pk}/`.

## 🔟 `school_system/urls.py` — Root URL Configuration

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),      # Django admin panel
    path("", include("core.urls")),        # Include all core app URLs
]
```
- `admin.site.urls` — automatically creates all admin panel URLs.
- `include("core.urls")` — includes all URLs from `core/urls.py` at the root level (no prefix).

```python
from django.conf import settings
from django.conf.urls.static import static

if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```
- **Only in development** (`DEBUG=True`): Django serves uploaded media files.
- This maps URL `/media/students/photo.jpg` → file `media/students/photo.jpg`.
- In production, a web server like Nginx serves media files, not Django.

```html
<!doctype html>
<html lang="en">

    />
  </head>
```
- Standard HTML5 boilerplate.
- Loads **Bootstrap 5** CSS from a CDN for styling.

```html
  <body>
    <nav class="navbar navbar-expand-lg navbar-dark bg-dark mb-4">
      <div class="container">
        <a class="navbar-brand" href="{% url 'home' %}">ITI School</a>
```
- `{% url 'home' %}` — **Django template tag**. Generates the URL for the view named `'home'`. Outputs `/`.

```html
        {% if user.is_authenticated %}
```
- `{% if %}` — Django template conditional. `user` is automatically available (from `context_processors.auth` in settings).
- `user.is_authenticated` — `True` if the user is logged in.

```html
        <li class="nav-item">
          <a class="nav-link" href="{% url 'home' %}">Home</a>
        </li>
        <li class="nav-item">
          <a class="nav-link" href="{% url 'student_list' %}">Students</a>
        </li>
        <li class="nav-item">
          <a class="nav-link" href="{% url 'logout' %}">Logout</a>
        </li>
        {% else %}
        <li class="nav-item">
          <a class="nav-link" href="{% url 'login' %}">Login</a>
        </li>
        {% endif %}
```
- If logged in → show Home, Students, Logout links.
- If not logged in → show Login link.

```html
    <div class="container">{% block content %} {% endblock content %}</div>
```

> [!IMPORTANT]
> **`{% block content %}{% endblock %}`** — This is the **template inheritance** system.
> - `base.html` defines a "hole" called `content`.
> - Other templates "fill" this hole with their own HTML.
> - This way, the navbar and Bootstrap are shared across ALL pages.

### `home.html`

```html
{% extends 'core/base.html' %} {% block content %}
```
- `{% extends 'core/base.html' %}` — "I inherit from base.html. Replace the `content` block with my content."

```html
<h1 class="display-5 fw-bold">Welcome, {{ user.username }}!</h1>
```
- `{{ user.username }}` — double curly braces = **output a variable**. Shows the logged-in user's name.

### `login.html`

```html
<form method="POST">
  {% csrf_token %}
```
- `method="POST"` — form data is sent in the request body (not in the URL).
- `{% csrf_token %}` — **REQUIRED for security**. Generates a hidden input with a random token that prevents Cross-Site Request Forgery attacks. Without this, Django rejects the form submission.

```html
  {% for field in form %}
  <div class="mb-3">
    {{ field.label_tag }}     <!-- Renders: <label>Username</label> -->
    {{ field }}               <!-- Renders: <input type="text" name="username"> -->
    {% if field.errors %}
    <div class="small text-danger">{{ field.errors }}</div>
    {% endif %}
  </div>
  {% endfor %}
```
- `{% for field in form %}` — loops through each field in the Django form (username, password).
- `{{ field.label_tag }}` — renders the HTML `<label>` element.
- `{{ field }}` — renders the HTML `<input>` element.
- `{{ field.errors }}` — shows validation errors (e.g., "This field is required").

### `student_form.html`

```html
<form method="POST" enctype="multipart/form-data">
```
- `enctype="multipart/form-data"` — **REQUIRED when uploading files**. Without this, the image field won't work. Normal forms use `application/x-www-form-urlencoded`, but file uploads need `multipart/form-data`.

### `student_list.html`

{% for student in students %}

    {% if student.image %}

- `{{ student.image.url }}` — generates the URL to the uploaded image (e.g., `/media/students/photo.jpg`).

## 1️⃣2️⃣ Quick Glossary — Key Terms

| Term | Meaning |
|------|---------|
| **ORM** | Object-Relational Mapper — write Python, Django writes SQL for you |
| **Model** | A Python class = a database table |
| **Migration** | Auto-generated SQL from your models. Run with `makemigrations` + `migrate` |
| **Serializer** | Converts Python objects ↔ JSON (like Forms but for APIs) |
| **ViewSet** | A class that combines list/create/retrieve/update/delete in one place |
| **Router** | Auto-generates URL patterns for ViewSets |
| **Decorator** | `@something` above a function — adds behavior (like `@login_required`) |
| **QuerySet** | A lazy database query — doesn't hit the DB until you iterate it |
| **ForeignKey** | A column that references another table (relationship) |
| **CSRF Token** | Security token to prevent forged form submissions |
| **Token Auth** | Client sends `Authorization: Token <key>` header instead of cookies |
| **ModelForm** | Form auto-generated from a model (for templates) |
| **ModelSerializer** | Serializer auto-generated from a model (for APIs) |
| **`write_only`** | Field is accepted in input but never shown in output (like passwords) |
| **`read_only`** | Field is shown in output but never accepted in input (like GPA) |
| **`related_name`** | Name for the reverse relationship (e.g., `student.grades.all()`) |

## 1️⃣3️⃣ How a Request Flows Through the System

### Template Request Flow (e.g., viewing student list)

```
Browser → GET /students/
    ↓
school_system/urls.py → include("core.urls")
    ↓
core/urls.py → path("students/", views.student_list)
    ↓
@login_required → Is user logged in? No → redirect to /login/
                                    Yes → continue
    ↓
student_list(request) → Student.objects.all() → SQL query
    ↓
render(request, "student_list.html", {"students": [...]})
    ↓
Django Template Engine → fills in {{ student.name }}, {% for %}, etc.
    ↓
Returns HTML response → Browser displays the page
```

### API Request Flow (e.g., GET /api/students/)

```
Postman → GET /api/students/  (Header: Authorization: Token abc123)
    ↓
school_system/urls.py → include("core.urls")
    ↓
core/urls.py → path("api/", include(router.urls))
    ↓
Router → matches "students/" → StudentViewSet.list()
    ↓
TokenAuthentication → reads token from header → finds user → sets request.user
    ↓
IsAuthenticated → Is request.user authenticated? No → 401 Unauthorized
                                                  Yes → continue
    ↓
StudentViewSet.list() → Student.objects.all()
    ↓
StudentSerializer(students, many=True) → converts to JSON
    ↓
Response([{...}, {...}]) → Postman displays JSON
```

## 1️⃣4️⃣ Common Instructor Questions & Answers

**Q: What's the difference between `Serializer` and `ModelSerializer`?**
> `ModelSerializer` auto-generates fields from a model (like `ModelForm`). Plain `Serializer` requires manual field definitions. Use `Serializer` when you're not doing direct CRUD on a model (like login).

**Q: Why use `ViewSet` instead of `APIView`?**
> `ViewSet` + `Router` gives you full CRUD (6 endpoints) in ~4 lines. `APIView` gives you more control but requires writing each action manually. Use `ViewSet` for standard CRUD, `APIView` for custom logic.

**Q: What does `on_delete=models.CASCADE` mean?**
> When the referenced object (e.g., Student) is deleted, all related objects (their Grades) are also deleted automatically. Other options: `SET_NULL` (set to NULL), `PROTECT` (prevent deletion).

**Q: Why both `subject` and `subject_id` in GradeSerializer?**
> `subject` (read_only) = shows full object `{"id":1, "name":"Math"}` in responses.
> `subject_id` (write_only) = accepts just an integer `3` in create/update requests.
> This pattern gives clean input and rich output.

**Q: What's the difference between `null=True` and `blank=True`?**
> `null=True` = database allows NULL. `blank=True` = form/serializer allows empty value. Use both together for optional non-text fields.

**Q: How does Token Authentication work?**
> 1. User logs in via `/api/login/` → gets a token string
> 2. User includes `Authorization: Token <string>` in all future requests
> 3. DRF reads the header, looks up the token in the database, finds the user
> 4. Sets `request.user` to that user
