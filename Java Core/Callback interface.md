### سؤال: يعني إيه كلاس `Timer` وبيعمل إيه في حياتنا؟

#### س1: تخيل إنك بتسلق بيض.. بتعمل إيه؟

ج:

أنت بتحط البيض في النار، وبتظبط "المنبه" (Timer) بتاع المطبخ على 5 دقايق.

المنبه ده جهاز غبي، وظيفته حاجة واحدة بس:

1. يعد 5 دقايق.
    
2. أول ما يخلصوا، يعمل صوت "ترررررن" (Event).
    
3. أنت لما بتسمع الصوت، بتجري تشيل البيض (Action).
    

هو ده بالظبط كلاس Timer في الجافا!

هو كلاس جاهز موجود في مكتبة اسمها javax.swing، وظيفته إنه يشتغل كـ "عداد وقت". بتقوله: "عد كذا ثانية، ولما تخلص، نادي عليا عشان أنفذ كود معين".

---

#### س2: الكلاس ده محتاج مني إيه عشان يشتغل؟

ج:

عشان تشتري منبه وتشغله، محتاج تظبط حاجتين:

1. **المدة (Delay):** هيرن كل قد إيه؟ (مثلاً كل 1000 مللي ثانية = 1 ثانية).
    
2. **المستمع (Listener):** مين الشخص اللي هيرد عليه لما يرن؟
    
    - المشكلة إن التايمر ده "أعمى". هو ميعرفش ينادي على "محمد" ولا "أحمد".
        
    - هو مبرمج إنه يدوس على "زرار" معين لما الوقت يخلص.
        

---

#### س3: إيه حكاية "الزرار" أو الإنترفيس `ActionListener`؟

ج:

تخيل التايمر ده علبة مقفولة طالع منها سلك. السلك ده لازم يتركب في "فيشة" معينة.

الفيشة دي هي الـ Interface اللي اسمه ActionListener.

- **التايمر بيقولك:** "يا عم المبرمج، أنا لما الوقت يخلص، ببعت إشارة كهرباء في السلك ده. هاتلي بقى أي **كلاس** (فيشة) بيفهم الإشارة دي وركبه فيا".
    
- **أنت بتعمل إيه؟** بتعمل كلاس (TimePrinter) وتخليه يركب الفيشة دي (`implements ActionListener`).
    
- **النتيجة:** لما التايمر يخلص عد، الشحنة بتمشي وتوصل للكلاس بتاعك، فتشغل الدالة اللي جواه (`actionPerformed`).
    

---

#### س4: إزاي بنكتب الكلام ده كود (ببساطة شديدة)؟

ج:

تعالى نترجم حدوتة البيض لكود جافا:

1. نجهز الشخص اللي هيشيل البيض (المستمع):
    
    لازم يكون معاه "رخصة" (Interface) إنه بيسمع المنبه.
    
    
    
    ```Java
    // ده الشخص اللي هيتحرك لما المنبه يرن
    class Person implements ActionListener {
        @Override
        public void actionPerformed(ActionEvent e) {
            System.out.println("أنا شيلت البيض من على النار!"); 
        }
    }
    ```
    
2. **نشتري المنبه ونظبطه:**
    
    
    
    ```java
    // 1. جبنا الشخص
    ActionListener mom = new Person();
    
    // 2. جبنا المنبه (Timer)
    // وقلنا له: رن كل 5000 مللي ثانية (5 ثواني)
    // ولما ترن.. نادي على "mom"
    Timer kitchenTimer = new Timer(5000, mom);
    
    // 3. شغل المنبه
    kitchenTimer.start();
    ```
    

### الخلاصة عشان الطفل الصغير يفهم:

- الـ **`Timer`**: هو منبه بيعد وقت.
    
- الـ **`ActionListener`**: هو الشخص اللي قاعد مستني المنبه يرن عشان يعمل حاجة.
    
- الـ **`actionPerformed`**: هو الفعل اللي الشخص هيعمله (يقفل النار، يطبع رسالة، يزمر).
    

---

هنربط الحدوتة دي بالمصطلح التقني المخيف **"Callback"** ونشوف إزاي كلاس `Timer` بيستخدمه عشان ينفذ اللي إحنا عايزينه.

### الجزء الأول: لحظة الـ "Callback" 📞

#### س1: هو ليه أصلاً اسمه "Call-back" (إعادة اتصال)؟

ج:

عشان نفهم الاسم، لازم نقارنه بالوضع الطبيعي:

1. **الوضع الطبيعي (Direct Call):**
    
    - أنت (المبرمج) بتكتب كود، وبتقول: "يا دالة `print()` اشتغلي دلوقتي".
        
    - أنت الفاعل، وأنت اللي بتأمر.
        
    - **الاتجاه:** أنت -> الدالة.
        
2. **وضع الـ Callback (الحدوتة بتاعتنا):**
    
    - أنت بتروح للـ `Timer` وتقوله: "خد الكلاس ده (المستمع)، خليه معاك، و**ابقى رن عليا أنت** لما تخلص عد".
        
    - هنا الآية اتقلبت! مش أنت اللي بتنادي الدالة، ده **التايمر هو اللي بيناديك** (Calls you back) لما الحدث يحصل.
        
    - **الاتجاه:** التايمر -> أنت.
        

**بالمختصر:** الـ Callback هو إنك تدي "رقم تليفونك" (الكود بتاعك) لحد تاني (التايمر)، وتقوله "كلمني لما تخلص".

---

### الجزء الثاني: دور الـ Interface (عقد الاتفاق) 🤝

#### س2: إزاي التايمر "الغبي" عرف يشغل الكود بتاعي "العبقري"؟

ج:

التايمر ميعرفش كلاس TimePrinter بتاعك، ولا يعرف إنك بتسلق بيض ولا بتطبع وقت. هو محتاج "وسيط" أو "لغة مشتركة" يتفاهم بيها معاك.

الوسيط ده هو الإنترفيس: **`ActionListener`**.

1. **التايمر بيقول:**
    
    > "أنا معرفش حد، بس أنا بتعهد إن أي حد يجيلي معاه كارنيه (Interface) مكتوب عليه `ActionListener`، أنا هنادي على الدالة اللي معاه اللي اسمها `actionPerformed`".
    
2. **أنت (المبرمج) بتقول:**
    
    > "تمام، أنا هعمل كلاس (`TimePrinter`) وهخليه يطلع الكارنيه ده (`implements ActionListener`)، وهحط الكود بتاعي جوه الدالة `actionPerformed`".
    
3. لحظة الربط:
    
    لما تبعت الكلاس بتاعك للتايمر new Timer(1000, listener)، التايمر بيمسك الكارنيه، ولما الوقت يخلص، بيدوس على الزرار الوحيد اللي يعرفه في الكارنيه: actionPerformed().
    

---

### الجزء الثالث: إسقاط تقني على الكود 💻

تعالى نشوف الكود تاني بعين "الخبير" بعد ما فهمنا الربط:



```Java
// 1. العقد (Interface):
// ده الشكل الموحد اللي التايمر بيفهمه
public interface ActionListener {
    void actionPerformed(ActionEvent event);
}

// 2. الكود بتاعك (The Callback Object):
// أنت هنا بتجهز "الرد" اللي التايمر هيناديه
class TimePrinter implements ActionListener {
    
    // دي الدالة اللي التايمر "هيرن عليها" (The Callback Method)
    public void actionPerformed(ActionEvent event) {
        System.out.println("الوقت خلص! صوت الجرس: ترررن");
    }
}

// 3. التشغيل (Registration):
public class Main {
    public static void main(String[] args) {
        // جهزنا الشخص اللي هيرد
        ActionListener listener = new TimePrinter();

        // ادينا رقم تليفونه للتايمر (Register Callback)
        Timer t = new Timer(1000, listener);
        
        t.start(); // التايمر بدأ يعد.. وهيكلمنا بعد ثانية
    }
}
```

الخلاصة في جملة:

الـ Callback Pattern هو إنك تمرر Object (شايل كود) لدالة تانية، عشان الدالة دي تنفذ الكود ده في وقت لاحق (لما حدث معين يحصل)، والـ Interface هو الضمان إن الدالة دي هتعرف تنفذ الكود ده.
